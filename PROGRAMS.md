# Program imports and progress compatibility

Programs & Backup accepts a program JSON file or pasted JSON (including fenced JSON). Review the preview, then Add program. Ordinary email text must be converted to JSON first; example-program.json is the template. Use a new program ID for a revised plan. Existing programs and their history remain available. Program selection is under Workout → Program & starting point when no workout is active.

Program schema: schemaVersion 1, id, name, sessions. Each session has a unique id, label, optional group, and exercises. Each exercise has a unique id within the session, name, and optional target, sets, reps, section, equipment, setup, instructions, loadGuide, video, unit, movementId and loadStep. IDs use letters, digits, underscores or hyphens. Sets, when supplied, are positive integers up to 1000. loadStep is a positive number, optional; no pounds or increment is assumed for new programs. A target can describe time, distance, circuits or other instructions. These are shown as instructions; automatic circuit/timer execution is not implemented. Missing sets defaults to one tracking set. Rest sessions use an empty exercises array.

No fixed week/day/exercise counts are used by the program UI. Sessions are ordered and may be grouped by week, phase, or any label. Finish advances to the next selected session and stops at program completion. Legacy three-day rotation retains its selected days across the original plan. A manually chosen starting point does not fabricate earlier completions. Select Week 4 in the session selector to resume there.

Storage uses workout-flow-v3. Existing ft2-flow-v2 data is migrated with original per-set records, notes, completion and active position preserved. Original ft2-journal-v1 logs are also read automatically. Original keys are never deleted. Invalid saved data blocks editing rather than silently overwriting it. No remote sync is added.

Backup export format 3 includes program definitions and complete state. Import previews and merges format 1 spreadsheet/original-app history, format 2 flow history, or format 3 full backups. Identical history is deduplicated. Original spreadsheet records are deduplicated by original session and date; reimport keeps existing records. Different active workouts are rejected to protect the in-progress session. Conflicting program definitions with the same ID are rejected. Export before importing. Imported spreadsheet totals are not expanded into guessed per-set values. Partial sessions retain dates, pain, energy and notes and are labeled in progress. Completed workouts and their set records are displayed in Recorded details.

Existing original program mappings are confined to plan-core.js migration code. History stores programId, sessionId and exerciseId, validated against the saved definitions. Previous-load lookup requires matching movementId and unit in the same program. New programs without movementId do not guess exercise equivalence.
